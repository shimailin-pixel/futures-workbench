# 期货基本面 + 技术面联合分析工作台

## 一、这是什么

一个自带缠论（chan.py 引擎）标注的期货行情研究工作台。主图是 K 线，可叠加：
- **笔 / 线段 / 中枢**（缠论结构）
- **买卖点**（一买/二买/三买/一卖/二卖/三卖）
- **实时行情推送**（新浪财经接口，盘中自动刷新）
- **期限结构曲线**（近远月价差与升贴水）
- **技术指标面板**、**多周期联动**、**基本面自动采集**

## 二、怎么打开（给非技术同事）

**在线版**：直接点分享链接即可，浏览器打开就能用，不需要装任何东西。

**本地版**（若拿到源码包）：
1. 确认已安装 **Python 3.10 或更高版本**（在命令行敲 `python --version` 查看）
2. 双击 `启动工作台.bat`，或命令行执行：
   ```bash
   python app/server.py
   ```
3. 浏览器打开提示的地址（默认 `http://127.0.0.1:8765/`）

> 缠论引擎与 ECharts 均已随包内置。基本面自动采集走**纯标准库直连**
> （urllib + pandas），无需 akshare 也能工作；装了 akshare 会自动作为备选路径。

## 三、目录结构

```
app/
  server.py         HTTP 服务与全部 API（标准库 http.server）
  symbols.py        品种元数据（交易所/合约/板块）
  indicators.py     技术指标计算
  chan_analysis.py  缠论引擎封装（笔/线段/中枢/买卖点）
  fundamentals.py   基本面数据采集与评分
  direct_sources.py 数据源直连（库存/现货基差/会员持仓）
  source_names.py   跨数据源的品种名称映射（代码为唯一索引）
  realtime.py       实时行情快照
  ai_context.py     AI 诊断上下文组装
  netcheck.py       网络连通性诊断
  vendor/chanpy/    chan.py 缠论引擎（Vespa314/chan.py 开源版）
  static/           前端（index.html / app.js / style.css / echarts.min.js）
skills/             行情历史数据脚本（新浪财经接口）
```

## 五、基本面数据覆盖情况

基本面面板有四块数据，**每块独立采集，互不拖累**（一块失败其余照常显示）：

| 数据块 | 数据源 | 覆盖 | 说明 |
|---|---|---|---|
| 交割仓单日报 | 上期所官网直连 / 郑商所 / 广期所 | SHFE INE GFEX | 上期能源中心（INE）归入上期所表；郑商所与大商所有反爬 |
| 期货库存序列 | 东方财富数据中心 | 43/44 品种 | 原油(SC) 用上期所注册仓单替代（交割口径） |
| 现货价与基差 | 生意社 100ppi | 39/44 品种 | 原油/氧化铝/玉米淀粉/苹果/红枣 源无现货报价 |
| 会员持仓排名 | 新浪财经 | 43/44 品种 | 原油(SC) 源未收录 |

**品种名称映射**：三个源各用各的中文名（生意社叫「热轧卷板」、东财叫「热卷」、
新浪吃的是品种代码），`source_names.py` 里以**品种代码为唯一索引**统一维护，
所以不会再出现「改了名字就查不到数据」的问题。

**AI 研判与面板数据严格一致**：AI 面板直接引用当前面板那一份数据（不会另采一次），
结果上会标出采集时间与数据指纹；若中途重新采集且数据变了，旧研判会被明确标记为
「数据已更新，基于旧数据」并置灰，不会再静默留着一份对不上的结论。若模型把缺失
臆写成 0 手、或给出与客观评分冲突的结论，结果顶部会出现红色警示条。

## 六、已知边界

- 数据源为公开行情接口，**仅供研究参考，不构成投资建议**；不保证 SLA，接口限流时会变慢
- 缠论结果受 K 线窗口影响：切换周期/数量会自动重算，窗口越大级别越高
- 「AI 诊断」面板需在 WorkBuddy 环境中打开才能调用云端大模型；其余功能不受影响
- **大商所（DCE）官网对程序访问启用了反爬验证（HTTP 412）**，其仓单日报取不到；
  该品种的仓单块会明确写出原因，其余三块正常
- **郑商所（CZCE）同样有反爬**，其仓单日报与持仓排名表取不到；
  该品种的库存与基差正常
- 云端沙箱与本机网络环境不同，个别源（东方财富 SSL、生意社限流）在线上可能比本地更慢；
  **本地版的数据完整度通常优于在线版**
