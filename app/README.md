# 期货技术面 + 基本面联合分析工作台

把「盘面行为」和「供需事实」拧在一起的一套本地工具。技术面回答"钱在往哪走"，
基本面回答"供需往哪走"，两者冲突时按 skill 的纪律降级结论，而不是硬给方向。

## 启动

```bash
pip install akshare                 # 可选，但强烈建议（基本面自动采集依赖它）
python app/server.py --port 8765    # 打开 http://127.0.0.1:8765
```

未安装 akShare 时服务仍可启动，页面顶部会提示，基本面数据块逐项显示"源不可用"，
技术面、期限结构、研究记录功能不受影响。

## 云端部署（在线分享链接）

`deploy/` 目录是本项目的**精简可发布副本**，用于部署成在线链接给同事直接用：

```bash
# 本地按云端方式自测（PORT 注入 + 绑定 0.0.0.0）
cd deploy && PORT=8899 python app/server.py
```

`server.py` 的启动约定：

- 存在 `PORT` 环境变量 → 用它作端口、绑定 `0.0.0.0`（云端部署路径）
- 不存在 `PORT` → 默认 8765 + `127.0.0.1`（本地路径，不会无意暴露到局域网）
- 存在 `OPEN_BROWSER` → 启动 1.2 秒后自动打开浏览器（本地双击 `启动工作台.bat` 用）

部署包内容（74 个文件 / 1.8 MB）：

```
deploy/
  app/            server.py 等 8 个模块 + vendor/chanpy + static/
  skills/…/futures_history.py     新浪财经历史行情脚本
  requirements.txt                 全是注释 —— 本项目零第三方 pip 依赖
  启动工作台.bat                    本地一键启动（Python 版本自检 + 自动开浏览器）
  README.md                        给非技术同事的使用说明
```

发布时用 `startCmd = python app/server.py`，`installCmd` 可跳过（无依赖可装）。

**云端环境的两点已知限制**（非代码缺陷）：

1. 云端出口到 `datacenter-web.eastmoney.com` 的 HTTPS 会被拦截 → 「期货库存」板块不可用。
   本机同接口正常。错误文案已翻译成可读说明，不再抛 SSL 堆栈。
2. 基本面数据源本身有覆盖范围限制（生意社只覆盖 55 个大宗品种、新浪不覆盖郑商所持仓排名），
   这些是正常的业务缺口提示，不是故障。

**akShare 版本兼容**：`app/fundamentals.py` 的 `_ak_call()` 会探测当前版本的签名，
只传该版本认识的参数；某些接口在新版里从「函数」变成了「函数列表」时自动取第一个可调用成员。
否则云端装到新版 akshare 会直接报 `unexpected keyword argument 'start_date'`。

## AI 研判

自动基本面区与综合诊断区各有一个 AI 按钮，调用大模型把采集到的读数写成**可追溯的
分析文字**——包含「我看到的数据 / 分析过程 / 结论 / 口径与局限」四段。

### 调用链路

```
浏览器  ──▶  POST /api/ai-context   （后端组装提示词，不做模型调用）
   │            └─ 技术面信号 + 基本面四块读数 + 人工判断，逐条带来源/等级/日期
   │
   └──▶  云服务 LLM  /.cloud/llm/chat/completions   （前端直连，流式）
            └─ SDK：@tencent-ai/workbuddy-cloud-sdk（本地副本 app/static/vendor/）
```

**模型调用必须由浏览器发起**：云服务规范禁止把 `/.cloud/llm/*` 挂到本地后端做代理。
后端只负责整理证据，模型负责叙述。

### 提示词纪律（app/ai_context.py）

- 只允许引用已采集的数据；提示词明令"不得推算、不得补齐、不得引入外部行情"
- 每条读数强制带**来源 / 等级 / 数据日期**
- 强制区分「数据显示」（事实）与「推断」（判断），模型输出里用不同措辞
- 数据缺口显式列出，禁止用推测填补
- 不产出买卖点位、目标价、仓位建议
- 缺口一律写「未获取」，**严禁把缺失写成 0 手 / 零变化**；结论的倾向与评分必须逐字引用
  【客观基本面评分】，不得另造「中性 / 评分 0」；清单外的品种、地区、新闻不得出现

### 研判与面板数据一致性（2026-11-27 修复）

曾出现「面板显示仓单 193,682、库存 181,673，AI 研判却写库存 0 手、5/20 日变化 0、
倾向中性评分 0、交割仓单未找到 C/ 品种」的情况。根因不是数据源，而是四条链路：

1. **旧研判残留**：AI 面板是模型生成的纯文本，与面板数据没有绑定，数据刷新后旧文本照常展示。
2. **二次采集漂移**：`/api/ai-context` 原本自己再跑一遍 `fund.collect()`；云端某块超时就会
   比用户眼前那份少一块，模型看到缺口便臆造数字。
3. **切品种竞态**：基本面请求没有序号保护，慢的旧品种响应会覆盖 `state.fundamentals`，
   于是「面板 HC、AI 上下文 RB」。
4. **模型幻觉**：缺数据时把「未获取」补成 0，还串进了无关品种（油脂、境外产地）。

修复后的三层保障：

| 层 | 机制 | 实现 |
|---|---|---|
| 同源 | 前端把**面板当前那一份** `state.fundamentals` 直接 POST 给 `/api/ai-context`；后端仅在缺失时回退重新采集 | `app.js runAI` / `server.build_ai_context` |
| 绑定 | 对「数据日期 + 四块读数 + 客观评分」算 12 位指纹；`/api/fundamentals` 与 `/api/ai-context` 返回同一个值。AI 结果带「数据基准条」（采集时间 / 评分 / 指纹）；指纹变化即插**过期横幅**并置灰旧结果 | `ai_context.data_fingerprint` / `syncAIStaleness` |
| 校验 | 检查模型是否复述了关键读数、是否把读数写成 0 手、是否给出与客观评分冲突的倾向/评分；命中即在结果顶部显示红色警示 | `app.js validateAIOutput` |

补充：`loadFundamentals` 加了请求序号防竞态；重新采集不再直接抹掉 AI 结果，改由指纹决定
「沿用」还是「标记过期」；`/api/ai-context` 在 `fundamentals_source=panel` 时以面板指纹为准
（保留 `computed_fingerprint` / `fingerprint_consistent` 供排查，避免 Python 对象与 JSON
反序列化后的类型差异造成误判）。

端到端验证脚本：`app/tools/verify_ai_consistency.js`（用本地假 SDK 模拟模型输出，
12 条断言覆盖「同源传参 → 幻觉告警 → 数据变更过期」全链路）。

### 实测输出（RB，2026-11-26）

- 客观基本面倾向偏多（评分 3）：库存 10,058 手处近 60 日 8% 分位、20 日去化 24,367 手、
  基差率相对 20 日均值 +1.69σ
- 模型结论：偏多，置信度中等；并指出**仓单 35,558 手与期货库存 10,058 手口径不同、
  不可直接合并比较**，以及**郑商所有效预报附注对 SHFE 品种不适用需人工核验**

### 连通性

云服务域名 `*.app.workbuddy.host` **直连可用**。若浏览器报「无法连接云服务」，
通常是代理软件对该域名的分流规则有问题（实测走系统代理 TLS 握手失败、直连正常）。

**工作台自带「网络诊断」按钮**（AI 面板右上角，失败时错误框里也有「立即诊断」）：

- 后端 `app/netcheck.py` 复刻浏览器的代理决策——读注册表 `ProxyEnable` / `ProxyServer` /
  `ProxyOverride`，按 WinINET 绕过列表规则判断该域名是否走代理；
- 分别实测「直连」与「经系统代理」两条链路，报告浏览器当前实际走哪条；
- 直接给出可照做的修复指令（代理软件的 DIRECT 规则 / 系统代理绕过列表 / 注册表项）。

诊断接口：`GET /api/net-check?endpoint=https://<云服务域名>`

修复办法二选一：

- 在代理软件里把 `*.app.workbuddy.host` 设为直连（DIRECT）
- 或把该域名加进系统代理的「绕过列表」（v2rayN：参数设置 → 系统代理设置 →
  多个代理绕过地址 → `*.app.workbuddy.host`）

> 注：v2rayN 在退出时会把内存中的配置写回磁盘。若在改配置前它已运行，
> 需重启一次 v2rayN 让新绕过列表生效。

## 实时行情

K 线与实时价全部来自**新浪财经**公开接口，无需任何凭据：

| 数据 | 接口 |
|------|------|
| 内盘日线 | `InnerFuturesNewService.getDailyKLine`（`stock2.finance.sina.com.cn`） |
| 内盘分钟线 | `InnerFuturesNewService.getFewMinLine` |
| 内盘实时快照 | `hq.sinajs.cn/list=nf_<代码>0`（GBK，44 字段） |

要点：

- **强制刷新**：所有 K 线请求走内存缓存（TTL 120 秒），带 `force=1` 会先做前缀失效再拉新，
  因此「刷新」按钮拿到的确实是新数据，不是 120 秒内的旧响应。
- **日线合并**：新浪日线接口盘中滞后一个交易日（09:30 时最后一根仍是上一交易日）。
  `realtime.merge_daily()` 用快照补出「当日进行中 K 线」，收盘后接口自更新时改为替换末根。
- **交易日归属**：国内期货交易日从前一晚 21:00 夜盘开始，跨零点夜盘（≤02:30）仍属该交易日；
  推算用 akshare 真实交易日历，能正确跳过春节与国庆（超出日历范围时退化为跳过周末）。
- **涨跌基准**：以**昨结算价**为基准（非当日开盘价），这是国内期货惯例。
  盘中结算价字段为 0，必须用 `parts[10]` 的昨结算价，否则涨跌全错。
- **成交量口径**：进行中 K 线的成交量置空、沿用接口原值——快照口径是交易日总量，
  与分钟线逐根增量不同，混用会产生约 25% 的口径偏差。
- **代码写法**：行情接口只认 `RB0` / `nf_RB0` / `rb2701` 这类带连续标记或月份的代码，
  裸字母（`RB`）会返回空 JSONP。`/api/analysis` 与 `/api/kline` 会自动归一，
  四种写法等价；`/api/realtime`、`/api/term-structure`、`/api/fundamentals` 直接收裸字母。
- **外盘行情未接入**：内盘 44 品种全部实测可用；外盘（hf_*）实时接口未纳入本工作台。
  但内盘 26 个品种的 `anchor`（锚定层）标记保留——该标记表示"该品种需人工核对
  汇率、进口利润与内外价差"，属研究纪律约束，与行情数据接入与否无关。

### 采集实现要点

- **直连优先、akShare 备选**：云端沙箱里 akShare 走 requests 会撞证书链
  （`datacenter-web.eastmoney.com` SSLError），而 urllib 用系统 CA 是通的，
  所以 `direct_sources.py` 用纯标准库直连同一批源，akShare 降为备选路径。
- **生意社反爬**：对 `Accept: */*` 会返回几百字节的 JS 混淆挑战页（解析不出表格），
  必须用 `Accept: text/html,...`；对并发访问会随机打空，所以**串行**抓。
- **基差批量抓取**：生意社日页本身就含全部 ~44 个品种，改成「一次 HTTP 取整页」
  （`shangshe_spot_day_all`）后，请求数从 `天数 × 品种数` 降到 `天数`，
  既快一个量级，也不再触发频率限制。
- **上期所仓单直连**：`shfe_receipt_day` 用 urllib 抓
  `shfe.com.cn/data/tradedata/future/stockdata/dailystock_YYYYMMDD/ZH/all.html`，
  逐品种一张表，「仓库」「厂库」两张表合并求和。数值与 akShare
  `get_shfe_receipt_3` 实测 100% 一致（23 个品种逐个对账通过）。
- **主力合约快路径**：用新浪批量行情一次取回各候选合约成交量定主力（0.14s），
  替代原先逐合约抓完整历史。
- **基差口径**：生意社页面的「现期差」列把数字与百分号拼在一起且精度有误
  （铜显示 `-72667.63%`），故只取现货价与合约价，基差自算
  `基差 = 合约价 − 现货价`、`基差率 = 基差 / 现货价`，与 akShare 口径一致。

### 缓存语义（踩过的坑）

`_memo` 的两级缓存（内存 + 磁盘）必须把**空结果当失败**处理：

- 早期版本只把 `None` 当失败，「空字典 `{}`」被当成成功结果按完整 TTL（1 小时）
  写进磁盘缓存 → 一次网络抖动就把该板块锁死一小时，之后一直返回空表。
  这是线上「基本面数据没有了」最难查的一个原因。
- 现在 `None / {} / []` 一律按失败处理，只缓存 60 秒；内存层同样区分 TTL。
- 磁盘缓存带 `_CACHE_VERSION` 前缀，改采集结构时递增即可让旧缓存自动失效。
- `stale_ok=True` 时采集失败会回退到**过期的真实缓存**（历史数据，不是推测值），
  配合各块的 `asof` 字段，用户能看到数据实际是哪天的。

### 已知缺口（不会被推测值填补）

- **大商所（dce.com.cn）** 对程序访问启用反爬验证（HTTP 412，首页同样被拦），
  仓单日报无法自动获取。其核心变量由「东财库存 + 新浪持仓排名」覆盖，
  缺口会在页面上显式提示，需人工查交易所日报。
- **郑商所（czce.com.cn）** 同样有反爬（HTTPError），仓单日报与持仓排名表取不到；
  其品种的库存与基差可用。
- **原油（SC）**：东财无库存序列、生意社无现货报价、新浪持仓排名未收录
  （同为能源中心的 FU/LU/NR 有数据，是新浪侧未收录 SC）。
  库存块改用**上期所注册仓单替代**（交割口径，已在界面上标注口径差异）。
- **生意社无现货报价**：氧化铝(AO)、玉米淀粉(CS)、苹果(AP)、红枣(CJ)。
- **Mysteel / SMM 类铁水、产量、表需数据**需付费授权，工具不采集，
  保留在决策面板的人工输入位。

### 口径提醒

- 生意社的现货价**含增值税**（农产品 9%、工业品 13%），期货价不含税。
  直接相减得到的"基差"会被税差放大，因此工具同时给出**除税参考基差**，
  并只用**基差率相对自身 20 日均值的偏离（z-score）**做方向判断——
  这是口径无关、可跨品种比较的读数。绝对基差仅供趋势参考，请以交易所现货核验。
- 库存分位使用近 60 个观测的分位数，而非首尾百分比，避免个别极值把相对变化
  放大成无意义读数。

## 期限结构：升水与贴水

期货价格是「未来某月交割时的现货价预期」。把同一条曲线上不同到期月的价格排开，
就得到期限结构；曲线的**倾斜方向**就是升贴水：

| 形态 | 特征 | 市场在说什么 |
|------|------|--------------|
| **升水 Backwardation** | 近月价 > 远月价，曲线向下倾斜 | 眼下货紧、以后会松 |
| **贴水 Contango** | 近月价 < 远月价，曲线向上倾斜 | 眼下货松、以后会紧 |
| **平坦 Flat** | 两者价差在年化 ±2% 以内 | 期限结构不提供方向 |

判定口径（`app/server.py::term_structure`）：

- **曲线端点**：近端取最早仍在交易的活跃合约，远端取主力之后较远的活跃合约；
  早先版本把「近月」定义成主力前一个合约，而多数品种主力就是第一个活跃合约，
  于是标签全部退化成「无独立近月」，把最有价值的升贴水信号整个丢掉。
- **剔除已摘牌合约**：交割月早于当前月的合约只剩最后一笔陈价
  （如 CU2610 停在 109,600，而 CU2701 才 87,950），挂在曲线上会把形态彻底带偏。
- **用年化幅度比较**：不同品种跨月数差异大，裸百分比不可比。
  年化 ±2% 以内记为平坦，2%~10% 为温和偏紧/偏松，>10% 为显著。
- **流动性门槛**：成交不足主力 1%（且 < 1000 手）的合约排除出月差计算。

接口额外返回 `concept`（概念白话）、`reading`（代入本品种数字后的读数）、
`caution`（注意事项）三段，前端直接渲染在期限结构面板下方。

### 期限结构曲线图

面板里除了文字与表格，还有一张真正的**曲线图**（ECharts）：

- **横轴**：合约到期月（面板内小图只显示月份数字，大图显示完整合约号）
- **上方主图**：期限价格曲线。线色即形态——升水=红、贴水=绿、走平=蓝；
  主力/近月/远月分别用蓝/橙/灰标签标在曲线上；左上角标注形态名与方向箭头
  （↘ 向下倾斜 = 升水，↗ 向上倾斜 = 贴水），年化幅度一并显示
- **下方副图**：各合约对主力的月差柱（正=红、负=绿），一眼看出月差符号
- **未入曲线的合约**：摘牌陈价 / 流动性不足的合约不画点（陈价动辄偏离数千点，
  画上去会把 y 轴拉爆、曲线压成平线），改为图下一行文字列出合约名与收盘价

## 缠论标注（chan.py）

图表上方「叠加缠论」按钮，把缠论结构直接画在 K 线上：

| 元素 | 画法 | 含义 |
|------|------|------|
| **笔** | 深蓝细线 | 相邻顶底分型连线，最小趋势单位 |
| **线段** | 紫色粗线 | 至少三笔构成的更大结构 |
| **中枢** | 橙色矩形 | 至少三笔重叠的价格区间，行情在区间内震荡 |
| **买点** | 红色向上三角 | B1 背驰一买 / B2 次低点二买 / B3 中枢突破回抽三买 |
| **卖点** | 绿色向下三角 | S1 背驰一卖 / S2 次高点二卖 / S3 跌破中枢反抽三卖 |

虚线表示**尚未确认**的元素（缠论的笔段在数据尾部随时可能重划）。

### 实现要点

- 计算用 **chan.py 官方开源版**（Vespa314/chan.py，MIT 协议），代码放在
  `app/vendor/chanpy/`，只保留计算部分，删掉了 matplotlib 绑图模块。
- chan.py 内置的 4 种数据源（baostock/akshare/ccxt/csv）都不覆盖国内期货，
  且 csv 源要求文件落在 `DataAPI/` 目录下 → `app/chan_analysis.py` 实现
  `CChanDataSource` 继承 `CCommonStockApi`，并用 `CChan` 子类覆写
  `GetStockAPI()` 直接返回它，**不改动 vendor 目录**。
- 配置取宽松档：`bi_strict=True`、`bi_fx_check="strict"`、`seg_algo="chan"`、
  `divergence_rate=inf`（不筛背驰，全部标出）、`min_zs_cnt=0`。
  期货日内波动大，默认背驰阈值会把大部分点滤掉，反而看不到标注。

### 三层坑（都踩过）

1. **坐标要落在原始 K 线上**。chan.py 有两层结构：`CKLine_Unit`（原始 K 线）
   和 `CKLine`（按包含关系合并后的 K 线）。笔/线段引用的是合并 K 线的 idx，
   直接用会让整张图错位。必须用 `bi.get_begin_klu()` / `get_end_klu()`
   换算回原始 K 线 idx。
2. **`data` 里不能混放索引和价格**。custom series 会把 data 的各维度都当 y 值
   参与轴范围计算，索引（0~300）会把 y 轴撑到从 0 起，K 线被压成一条扁带。
   解法：`encode: {x: 0, y: 1}` 明确指定哪一维是坐标，data 填
   `[x1, y1, x2, y2]` 四维，后两维只给 `renderItem` 取终点。
3. **分钟线的时间戳不能丢时分**。日线归零时分没问题，分钟线若也归零，
   同一天多根 K 线时间戳相同 → chan.py 直接报 `kline time err`。
   同时 `CTime` 的 `auto=True` 会把 00:00 映射到当天 23:59，
   分钟线必须整批关掉 `auto`。

### 切换周期时缠论错位（已修）

用户反馈「切换周期的时候缠论会出错」。实际有**四个独立成因**，都已修：

| # | 症状 | 成因 | 修法 |
|---|------|------|------|
| 1 | 关掉缠论后图层还在；切到 5m 后 1d 的标注还盖在上面 | ECharts `setOption` 默认是 **merge** 语义，新 series 数组比旧数组短时旧尾巴被完整保留 | 主图 `setOption(..., { replaceMerge: "series" })` 整组替换 |
| 2 | 切换周期后标注整体偏移几根 K 线 | 缠论那批 K 线与图表那批 K 线窗口不一致（analysis 301 根 / chan 300 根；缓存 120s 过期后分钟线还会滚出新 bar） | 前端 `alignChan()` **按时间戳**（不是序号）把每个元素重新映射到图上那根 K 线，映射不到就丢弃 |
| 3 | 慢的旧请求回来把新周期的缠论盖回去 | 切周期会连发多次 `/api/chan`，没有并发防护 | `state.chanReq` / `state.loadReq` 请求序号，过期响应直接丢弃 |
| 4 | 切周期后图上空的，或按钮状态错乱 | 开关状态绑在 `state.chan` 上，切周期时它被清空 | 开关状态独立存 `state.chanOn`，切周期/改数量后**自动重算**缠论 |

另修两处隐患：

- **笔/线段原本每条建一个 series、每条都塞全部数据** → N 笔画 N×N 条重合线
  （8 笔 = 56 次重绘）。改成笔、线段各一条 series。
- **价格吸附**：两次取数的 K 线快照若不一致（盘中日线末根被刷新），
  笔的端点可能落在图上那根 K 线的高低点之外，`alignChan()` 把价格夹回该 bar 的实际区间。

还有一处**后端时间戳坑**：分钟线的夜盘会有 `00:00` 的 bar（1h / 30m 周期常见），
若时间戳只输出日期，前端按时间对齐时就找不到这根 K 线，落在它上面的笔/线段/买卖点
会被整段丢弃。`chan_analysis._klu_index_map()` 现在对分钟线**一律输出 `YYYY-MM-DD HH:MM`**。

验证脚本：

| 脚本 | 作用 |
|------|------|
| `app/tools/verify_chan_api.py` | 接口层交叉验证：4 品种 × 4 周期 + 4 档 count，用时间戳把 `/api/chan` 的每个元素对到 `/api/analysis` 那根 K 线上，比对价格是否落在其高低点区间内 |
| `app/tools/verify_chan_align.js` | 浏览器层：逐周期 × 逐数量校验图上渲染出来的端点价格，并检查残留图层与 Y 轴范围 |
| `app/tools/verify_chan_switch.js` | 切换周期的截图证据 |
| `app/tools/verify_chan_multi.js` | 8 品种回归 |

### 边界说明

买卖点是**形态学标记，不是交易信号**。缠论对走势的划分本身有多义性——
同一段行情换个参数（`bi_fx_check`、`seg_algo`）可能给出不同的笔和买卖点。
作者本人也声明"这可能是他理解的缠论"。请结合趋势结构、量能与基本面自行判断。

## 客观基本面倾向

`/api/fundamentals` 会把采集到的客观读数折算成一个评分（-6 ~ +6）与倾向标签，
**只使用可量化读数，每一条都可追溯到具体数据块**，不掺入主观判断：

| 读数 | 计分 |
|------|------|
| 库存处于近 60 日低/高分位（≤25% / ≥75%） | ±1 |
| 20 日库存累积/去化（幅度 ≥3%） | ∓1 |
| 基差率偏离 20 日均值 ≥1σ | ±1 |
| 现货升贴水幅度 ≥4% | ±1 |
| 仓单日变化 ≥2% | ∓1 |
| 前 20 会员多空比偏离 1 达 4% | ±1 |

综合诊断页做**三方对照**：技术面 / 客观基本面 / 人工判断，并识别三类冲突——
方向冲突、主观与客观不一致、否决权变量冲突。

## 纪律约束

- 每条数据都带来源、等级与数据日期；没有来源和时点的数字不进入结论。
- 采集失败的数据块返回明确原因，其余块照常工作，**不做数值补齐**。
- 客观基本面评分只读数、不判断；人工判断与客观读数冲突时，诊断页要求先解决分歧。
